예제 1 — 수정된 커피 부스 (속성 · DataTable · Method)

손님마다 레시피 수가 달라요: 1개 50%, 2개 30%, 3개 20%. 서비스 시간은 지수분포지만 평균이 레시피 수에 따라 3 · 4 · 5분.

Plant Sim 에서 만드는 순서

  1. 사용자 정의 개체: MUs 의 Part 를 복제 → MyObjects 폴더로 → 이름 바꾸기(myEntity) → 속성 aNoRecipes 추가
  2. myEntity 에서 파생(Derive) myEntity1·2·3 만들고 aNoRecipes = 1, 2, 3
  3. DataTable tbEntity 에 MU 이름과 비율(0.5/0.3/0.2) → Source 의 MU selection 을 Percentage 로, 표 지정
  4. 처리시간을 타입별로: Processing time 을 DataTable/Formula 로 (aNoRecipes 에 따라 3·4·5분)
  5. Variable: vTotal(누적 손님), vWIP(시스템 안 손님)
  6. Method: mCustArrival(Source exit → 도착 시각 기록, vWIP+1), mLeaveSys(Drain entrance → 퇴장 시각, tbSystemLog 에 한 줄, vWIP−1)
  7. Display/Chart 로 버퍼 대기 인원 모니터링, 평균 체류시간 보고
-- mCustArrival (Source 의 Exit control)
vTotal += 1
vWIP   += 1
@.aArrTime := EventController.SimTime   -- @ = 이 메서드를 부른 MU

-- mLeaveSys (Drain 의 Entrance control)
vWIP -= 1
tbSystemLog.writeRow(1, tbSystemLog.yDim + 1, @.name, @.aNoRecipes,
                     @.aArrTime, EventController.SimTime,
                     EventController.SimTime - @.aArrTime)
디버깅 팁Watch 창에서 @ 는 메서드를 부른 MU, ? 는 메서드를 부른 객체예요 (5장 익명 식별자).
연습 3기대 서비스 시간 → 시뮬레이션으로 확인
풀이
E[S] = 0.5×3 + 0.3×4 + 0.2×5 = 1.5 + 1.2 + 1.0 = 3.7분. ρ = 3.7 / 6 = 0.617. (서비스가 섞여 있어 더는 지수분포가 아니니 M/M/1 공식이 정확히 맞진 않아요 → 시뮬레이션이 필요한 이유!)

분기(Diverging) · 합류(Converging) · 블로킹

분기 — 기본 Exit strategy

후속 객체가 여럿이면 차례로(Cyclic) 보냄. Exit strategy 를 바꾸거나 FlowControl 객체로 변경. MU 속성(예: aNoRecipes)으로 갈 곳을 정할 수도 있음. Source·Buffer·Station·FlowControl 등이 분기점이 될 수 있어요.

합류

여러 곳에서 들어오면 도착 순서(FIFO)대로. 후속 객체가 차 있으면 MU 는 그 객체의 Forward Blocking List 에 이름을 올리고 기다림.
Exit strategy후속 객체가 차 있으면
Non-blocking (기본값)다음 후속 객체로 넘어가 보냄 — 빈 곳 아무 데나
Blocking정해진 후속 객체가 빌 때까지 기다림 → 그 동안 이 스테이션은 Blocked 상태

직렬 라인에서 스테이션 사이 버퍼가 0이면 다음 스테이션이 바쁠 때 앞 스테이션은 일을 끝내고도 부품을 못 넘겨서 Blocked 가 돼요. 컨베이어 AS-IS 라인의 핵심 손실이 이거예요.

연습 4버퍼 크기와 블로킹

버퍼를 0 → 5로 늘렸을 때 일어나는 일로 옳은 것은?

해설
버퍼는 두 스테이션의 변동을 서로 떼어 놓는(decoupling) 역할. 평균 능력은 같아도 버퍼가 없으면 "앞은 끝났는데 뒤가 바쁨"·"뒤는 놀고 있는데 앞이 아직" 상황이 생겨 처리량을 잃어요. 팀 프로젝트의 "버퍼 0/2/5/10" 실험이 바로 이것.

예제 2 — 밀링 병목과 병렬 스테이션

CutToSize → Milling 순서인데 Milling 이 병목이라 더 효율적인 두 번째 밀링기(3분)를 병렬로 추가하려 해요. CutToSize 다음에 두 밀링기로 분기, 각자 처리시간이 달라요.

병목 찾기

스테이션별 이용률 \(\rho_i = \lambda \cdot E[S_i] / c_i\) 가 가장 큰 곳이 병목. \(\rho \ge 1\) 이면 대기열이 끝없이 늘어요.

연습 5병목 계산 → 기계 추가 효과

도착 평균 5분 간격, CutToSize 균등(3,5), Milling 균등(5,7).

풀이
CutToSize: 4/5 = 0.8. Milling: 6/5 = 1.2 > 1 → 불안정(병목). 추가 후 능력 = 1/6 + 1/3 = 0.5개/분 > 도착률 0.2개/분 → 안정. Plant Sim 실습에서 Milling2 를 추가해 확인해요.

재귀 모델: 약사는 한 번에 레시피 1개만

손님이 레시피 하나를 받으면 남은 레시피가 있을 때 다시 줄 뒤로 가요. 구현: TakeCoffee 에 들어갈 때 mJobProc 가 @.aNoRecipes -= 1, 나갈 때 0 이면 Drain, 아니면 버퍼로 되돌림. 되돌아오는 손님 때문에 버퍼가 붐비니 Capacity 를 8로 늘려요.

예제 3 — 조립(Assembly) · 분해(Dismantle) · Sorter

AssemblyStation

메인 MU 에 부품(mounting parts)을 붙임 (차체 + 도어·펜더). Assembly table: 각 선행 객체에서 몇 개(Predecessors) 또는 MU 타입별 몇 개. Assembly mode: Delete MUs(부품 삭제) / Attach MUs(메인 MU 에 싣기). Exiting MU: Main MU 또는 New MU.

DismantleStation

메인 MU 에서 부품을 떼어 내거나 새로 만듦. 예: 컨테이너 1개 + 아이템 4개를 조립 → 나중에 분해해 컨테이너는 되돌려 보냄(Detach MUs).

Sorter

Buffer 대신 쓰면 우선순위대로 꺼냄. 예: 레시피 적은 손님 먼저 → 1잔 손님 대기 ↓

예제 4 — Experiment Manager 로 점원 수 최적화

창구 1개 드라이브스루. 도착 포아송 시간당 10명, 서비스 지수 평균 8분. 창구 앞 공간 6칸(서비스 중인 차 포함) — 다 차면 도착한 차는 떠남. 공간 1칸 월 $500, 손님 1명당 이익 $3, 점원 1명 월급 $4,000. 1달 = 30일, 실험 1회 = 12개월, k = 1~4.

  1. 점원 k명 → ParallelStation 의 X-dimension = k
  2. 출력 변수 vProfitPerMonth, vCostForHiring, vTotalProfit 정의 (EndSim 메서드에서 계산)
  3. ExperimentManager: Output values(vTotalProfit), Input values(ParallelStation.XDim — 속성 창에서 이름 찾기), Experiment design(1,2,3,4)
  4. 실행 → 리포트에서 평균·신뢰구간 비교
연습 7비용 계산 + 실험 실행
풀이
4,000×2 + 500×6 = 11,000. 6칸에 서비스 중인 차 2대 포함 → 줄 서는 칸 4 (Buffer capacity = 6 − k).

실습의 실험 결과로 보면 이익을 최대로 하는 k 는?

해설
k=1 은 ρ = 8/6 ≈ 1.33 으로 손님을 많이 잃고, k=3 부터는 더 받는 손님이 거의 없는데 월급만 늘어요. 신뢰구간이 겹치지 않는지도 확인!

예제 6: 라우팅 표

확률 0.6 → myProduct1, route = {1, 2} (절단 → 굽힘). 확률 0.4 → myProduct2, route = {2}. 개체마다 aRoute 표(순서별 스테이션·처리시간)와 현재 순번 aCur 를 두고:

  • Source 의 MU selection = Percentage (0.6 / 0.4)
  • mFCbf, mFC: @.aRoute[1, @.aCur] 로 다음 목적지 결정, 이동 요청
  • mProc: 처리시간을 aRoute 에서 읽어 설정, @.aCur += 1
연습 9이용률로 먼저 점검
풀이
λ = 4/60 개/분. 절단: 0.7 × (4/60) × 10 = 0.467. 굽힘: (4/60) × 20 = 1.33 > 1 → 1대면 대기열 폭주! 청동: (4/60) × 20 / 3 = 0.444 (삼각 평균 = (10+20+30)/3 = 20). 예제 6 절단: 0.6 × (4/60) × 10 = 0.4.
숫자를 그대로 넣으면 굽힘이 불안정하니 모델을 돌리기 전에 이렇게 이용률부터 확인하는 습관을 들여요. Plant Sim 실습에서 직접 확인해 보세요.
